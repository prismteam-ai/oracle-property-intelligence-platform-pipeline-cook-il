## Intent

A roofing CRM and its agents can discover aged-roof and open-roofing-permit leads within a map radius over real, reconciled Cook County IL property/permit/contractor/BBB data that Oracle continuously ingests and publishes as independently retrievable, CID-addressed IPFS snapshots at near-zero ongoing hosting cost.
**Proven? Partially.** County-scale data (1.86M properties, 1.61M permits, 33.6k contractors, 1.21M businesses, 2.69M sales, 99.8% with coordinates) is queryable via UI, SQL, agent and MCP with per-row provenance and CID footers; publication is manifest/CAR/CIDv1 with a verified previous-CID chain. Gaps: only ONE independent public gateway serves the bytes; the run the runtime serves by default is uncommitted and unverified; BBB coverage is 21 contractors; the runtime goes down for the duration of each pipeline run; MCP `findProperties` ignores `minRoofAgeYears`.

## Hiring signal

Strengths: real county-scale ingestion (10.4M rows) with hash-based deltas, watermarks, resume and idempotent reruns proven by DuckDB integration tests (22 test files, all green in 7 s); honest verification records that log failures as failures; contractor identity edges in kit vocabulary; robots-first BBB harvest that stops on 403; AI SDK agent with Zod tools and session memory; clear docs of source limits; delivered in under 6 h.
Weaknesses: two-gateway criterion unmet; single pin provider after Pinata 500; served run uncommitted/unverified; pipeline writes lock the served DB (availability coupled to ingestion); MCP roof-age filter bug; BBB coverage near zero; CDK stack synthesized but undeployable (Lambda has no dataset source) while real hosting is a VM; `verify-ipfs.yml` has never produced a record though docs claim it ran.
Material risks: SQL guard is regex-only — `read_text('/proc/self/environ')`, `read_csv('/etc/passwd')`, `glob('/**')` likely reachable from unauthenticated tRPC `query.sql` and MCP `queryDataset` (plausible, not executed); no rate limit on those endpoints; failed 6-hourly runs are silent (compose loop swallows exit).
Follow-up questions: (1) How would you get every CID served by a second independent gateway and prove it without depending on ipfs.io rate limits? (2) Why does the web app read the same DuckDB file the pipeline writes, and how would you decouple serving from ingestion? (3) What does the CDK stack deploy today, and would it serve the dataset if `cdk deploy` ran? (4) Why does MCP `findProperties` return null-roof-age rows for `minRoofAgeYears: 15`?

## Pain points → concrete fixes

1. Only one independent gateway serves bytes → add gateways not rate-limited by default (self-hosted Kubo with `origins` multiaddrs in the manifest, w3s.link via web3.storage pin), retry ipfs.io/dweb.link with long backoff from a different IP in CI, and fail `publish` when fewer than two independent gateways verify.
2. Pinata 500 leaves one pin → retry/backoff on Pinata or add a third provider; exit non-zero when <2 pins ok.
3. Run 20261110T221716Z published but unverified and uncommitted → run `pipeline verify --run 20261110T221716Z`, commit manifest + verification + run.json (publications/20261110T221716Z/).
4. Outage during runs → publish-then-swap: transform into a new DuckDB file and atomically rename, or serve Parquet via read-only views; current per-query open is a half-fix (uncommitted `db.ts` in working tree).
5. MCP `findProperties` ignores `minRoofAgeYears` / counts radius-only → apply the same predicate as the UI and exclude null roof ages; add a test with a null-roof fixture (apps/web/src/mcp).
6. SQL guard → `SET enable_external_access=false` (or `allowed_paths`) after creating views in apps/web/src/db/duck.ts; add rate limiting on `query.sql` and `/mcp`; use `crypto.timingSafeEqual` for the bearer compare (apps/web/src/server.ts:99).
7. Silent failures → non-zero exit from the 6 h loop and a webhook/PagerDuty Events v2 call when `run.status='failed'` or dead letters > 0; incremental dead letters are orphaned (`inc-<run>` never redriven) → retry on next run.
8. CDK stack cannot run the app → wire Lambda to pull `cook_il.duckdb`/Parquet from `ARTIFACTS_BUCKET` and consume `VITE_API_URL`, or remove the stack and state "Docker only".
9. Docs drift → `docs/sources.md`/`county-findings.md` still say BBB not harvested; `docs/web.md` claims GH-Actions verification with no record; sources page shows "n/a" for the fetching run.
10. Roofing classifier noisy and BBB match rate 0 on shown rows → tighten `is_roofing` keyword rules and widen contractor name matching (498/8,810 open roofing permits linked).
